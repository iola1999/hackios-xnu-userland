# rebase-26：Mesa 26.x 移植层（`REBASE=26 tools/mk-mesa.sh` 时应用）

应用顺序（在 mk-mesa.sh 的 tar 解包之后、原有 `tools/mesa/*.patch` 循环之后）：

1. 原有 `tools/mesa/*.patch` 照旧应用；在 26.2.5 上有 9 个文件的部分 hunk 失败，属于预期情况，失败明细见顶层 `docs/analysis/mesa-rebase-2026-10.md` 第 2 节。
2. `0001-fd6-indirect-buffer-wfm-a8xx.patch`（upstream 2ee0a5e6）与 `0002-fd6-query-barriers-gen8.patch`（upstream 779cdb8e）：两个 a8xx 修复在 26.3-branchpoint 才有，26.2.5 上 cherry-pick 干净；若改用 26.3.x 基准则这两个可以去掉。
3. `0003-restore-osmesa-26.x-drift-adaptations.patch`：回滚 upstream 的 OSMesa 删除（027ccd963b）、以 25.0.7 的已打补丁版本恢复 osmesa 前后端（内容已包含 osmesa-es-profile 与 freedreno-darwin 的 osmesa hunk，因此那两个旧补丁的这些 hunk 必须处于跳过状态），并带上 26.x 接口变化的全部适配（glapi 包含路径、driParseConfigFiles 新签名、postprocess 剥离、u_sync_provider darwin 条件排除、libglapi_bridge 强制链接以导出 gl* 等）。
4. `0004-turnip-msm-darwin.patch`：Turnip（Vulkan）在 iOS 上经 msm 后端和 `tools/mesa/annibale-drm` 访问内核的 `AnnibaleGPU`，用 `TURNIP=1 REBASE=26 tools/mk-mesa.sh` 构建。Turnip 单独构建时定义 `HAVE_LIBDRM`，Vulkan 运行时才能经 `drmGetDevices2` 找到设备；Darwin 上为 Turnip 编译 `u_sync_provider.c`；缓冲区映射改为调用 `annibale_drm_map`；`cache_ops_aarch64.c` 在 Darwin 上从 sysctl `hw.cachelinesize` 获取缓存行大小，因为 XNU 不允许 EL0 读取 `CTR_EL0`。补丁在 `REBASE=26` 时总会应用，除 `cache_ops_aarch64.c` 外，改动只在构建 Turnip 时生效。
5. `0004-a830-no-early-preamble.patch`：A830 的设备表关闭 `has_early_preamble`。开启时，若 gallium 绘制中的片段着色器经 bindless fb-read 描述符读取帧缓冲，GPU 会停住（CP 已取完命令，HLSQ 一直忙）；关闭后同样的绘制都能完成。实测见顶层 `docs/progress/2026-10-30-ios26-usable-desktop.md` §4.3。
6. `0005-linear-import-last-level-padding.patch`：线性导入的末级行数非 4 的倍数时，`fd6_layout.c` 补齐后的布局可能超过 IOSurface 的分配（45x42 RGBA16Float，每行 384 字节，布局 16896 字节，分配 16384 字节）。单级单层线性导入只要各行都落在内存内仍然接受，资源标记 `sysmem_only`，绘制时不使用 GMEM，不触及补齐的行。实测见顶层 `docs/progress/2026-10-30-ios26-usable-desktop.md` §5。
7. `0006-a830-no-fs-tex-prefetch.patch`：A830 的设备表再关闭 `has_fs_tex_prefetch`，在 0004 之后应用。开启时，若片段着色器在开头直接使用插值坐标读取纹理，ir3 会将其改为着色器启动前的预取，QuartzCore 的 `glass_background_no_bleed_lph`（纹理 4、采样器 1）预取读到的距离场全为 0，Dock 玻璃的片段全部被丢弃；关闭后同一读取得到正确的距离场，Dock 与搜索栏显示完整的玻璃。上游已对 A810 与 a8xx_gen2 关闭这一项，A810 的注释写着 A830 可能也需要。实测见顶层 `docs/progress/2026-10-31-boot-order-and-performance.md`（`bo51`）。
8. `0007-ir3-retry-spilling-stage-without-preamble.patch`：用了私有内存的 stage 打印一行 `ir3[进程 pid]:`（私有内存字节数、`max_reg`、preamble 指令数，每进程前 64 行）；任务环境变量 `ANNIBALE_IR3_SPILL_RETRY=1` 时，对有 preamble 的这类 stage 关闭 preamble 重新编译一次，保留私有内存更少、或私有内存相同而寄存器更少的一份。未设置该变量时只额外打印上述信息。`kernel-12377-rate1-rt1` 里这类 stage 只有 11 个，在 SpringBoard 与 iconservicesagent，backboardd 没有；已重新编译一批，尚未运行。
9. `0008-u-trace-annibale-pass-times.patch`：任务环境变量 `ANNIBALE_PASS_TIMES=1` 打开 Mesa 的 GPU 时间戳，按 pass 种类（画布尺寸、GMEM bin 数、颜色附件数、深度／模板格式）每 5 秒汇总一行 `pass times`；`fd_trace_read_ts` 去掉 `FD_BO_PREP_NOSYNC` 加 10 ms 睡眠的轮询，直接阻塞等待，这一处对所有打开 u_trace 的用法生效。读法见顶层 `docs/analysis/2026-11-02-120hz-after-gpu-clock.md` §6。
10. `0009-fd-resource-contents-undefined.patch`：新增 `fd_resource_contents_undefined()`，把资源标为内容无效，下一个绘制到该资源的 batch 不再把它读回 GMEM；上一个写入它的 batch 仍会写回。AIR 在 Metal pass 的第一次绘制前，对 `MTLLoadActionDontCare` 的颜色附件调用它。CoreAnimation 整屏 pass 的第二个 RGBA16Float 附件属于这种情况，此前每个 bin 都读回，见顶层 `docs/analysis/2026-11-02-120hz-after-gpu-clock.md` §6。
11. `0010-fd-no-store-of-masked-cbufs.patch`：batch 结束时不写回当前混合状态禁止写入的颜色附件（`colormask` 为 0）。混合状态变化也触发附件的读写登记，禁止写入的附件按读入登记。CoreAnimation 整屏 pass 的颜色 1 由管线的 `writeMask 0` 关闭，此前每个 bin 都写回。`kernel-12377-rate8-ns1` 对 r8a：tile store 合计 3.33 → 2.76 s，整屏 pass 每次 808 → 787 µs，手势帧率在轮次间波动范围内，截图无差异，见顶层 `docs/progress/2026-11-05-defaults-and-charging.md`。
12. `0011-fd-shared-no-shadow.patch`：freedreno 不再对导入的资源（`fd_resource_from_handle` 设置 `is_shared` 的资源）做 shadow。shadow 会替换资源的 bo 并在批次结束后释放旧 bo，而 AIR 对导入的缓冲只在创建时映射一次，替换 bo 之后它写入的是驱动要释放的内存；`util_copy_rect` 行拷贝里的 SIGSEGV 由此而来，补丁说明记录了两轮的崩溃地址与拷贝长度。
13. `0012-fd-shadow-guard-probes.patch`：诊断用。`freedreno_resource.c` 统计 shadow 的调用、拒绝与替换 bo 次数，第一次拒绝、第一次替换 bo 和进程退出时各打印一行 `rwa shadow:`；`u_format.c`、`u_surface.c`、`u_transfer.c` 和 `freedreno_resource.c` 的拷贝与映射处调用 `tools/mesa/air/air_metal.c` 的 `rwa_*_guard`，指针不可能是地址时打印一行，拷贝记录写入 AIR 库的环形缓冲，进程收到 SIGSEGV 时打印。
14. `0013-fd-transfer-stride-after-shadow.patch`：`fd_resource_transfer_map` 在 shadow 成功后按新布局重新获取 `stride` 与 `layer_stride`。传输的 stride 在调用 shadow 之前就已从旧布局获取，不重新获取时映射偏移和调用方逐行拷贝用的是两套布局。
15. `0014-perf-probes-26.x.patch`：旧的 `draw-perf*.patch`、`fd-*.patch`、`fd6-*.patch`、`perf-*.patch` 在 26.2.5 上部分 hunk 失败，这个补丁补齐真机库里的状态：`fd_bo_cpu_prep` 与 `fd_perf_us` 只在 `FD_PERF_DRAW=1` 时计时；`fd6_draw.cc` 按段计时，超过 50 ms 的段打印 `fd draw seg slow`；批次切分计数；定义旧补丁只声明的 `fd_perf_cache_misses`（缺少该定义时库无法完成链接）；去掉 `ir3_cache.c` 里重复的一次未命中计数。
16. `0015-fd-bo-heap-null-check.patch`：`fd_bo_heap_alloc` 在 `calloc`、`fd_bo_new` 或 `fd_bo_map` 返回 `NULL` 时释放已持有的锁与引用并返回 `NULL`，防止分配或映射失败时解引用空指针。
17. `0015-ir3-disk-cache-darwin-uuid.patch`：Darwin 的 ir3 磁盘缓存使用所在 Mach-O 库的 `LC_UUID` 区分构建；未设置 `MESA_SHADER_CACHE_DIR` 时按 UUID 创建 `/private/var/db/annibale-ir3cache/<UUID>`。补丁还设置跨 UID 共享所需的目录与文件权限，并记录命中和写入次数。顶层 arm64e 构建启用 `shader-cache`，`mk-mesa.sh` 的独立构建仍默认关闭；跨开机验证见[ir3 磁盘缓存记录](https://github.com/iola1999/hackios-redmi-k90-annibale/blob/main/docs/analysis/2026-11-09-ir3-disk-cache.md)。
18. `0016-nir-lower-fb-read-zero-layer.patch`：在 `nir_lower_fb_read.c` 中，若片元着色器未从顶点阶段读入 `VARYING_SLOT_LAYER`，将帧缓冲读取坐标的图层绑定为立即数 0，避免 `ir3_nir_lower_layer_id` 生成未链接的 `load_input(VARYING_SLOT_LAYER)` 并从 VPC 未初始化的脏寄存器 `r1.z` 读取非零图层编号，导致 Adreno A830 单图层 2D 目标数组越界返回全零颜色。
19. `0017-nir-yuv-explicit-lod.patch`：YUV 平面采样接受 `nir_texop_tex`、`nir_texop_txl`、`nir_texop_txb` 与 `nir_texop_txd`，生成平面纹理指令时保留原操作，支持显式 LOD、bias 和导数采样。
20. `0018-ir3-alias-relative-and-fsat.patch`：移植上游 `8511f446` 与 `5a9db0be`，相对常量输出保留原 MOV，`fsat` 仅合入浮点 cat2/cat3 指令的饱和标记。实际 ir3 回归测试在旧版复现 3 项失败，修复后 16 项通过；隔离 iOS arm64e 目标库已链接，GPU 像素待验。运行方法与范围见 [ir3 输出优化测试](../tests/README.md)。
21. `0019-fd6-zero-unbound-texture-slots.patch`：`fd_set_sampler_views` 保留调用方显式传入槽位范围中的尾部空视图槽位，并在 `fd6_texture_key` 中记录 `num_textures`，使 `CP_LOAD_STATE6_0` 对未绑定的可空纹理槽位写入全零硬件描述符（`dummy_view`）；同时在 `fd_launch_grid` 恢复已保存的 3D `ctx->batch` 时调用 `fd_context_all_dirty`，防止计算核分发末尾 `fd_context_all_clean` 清空 3D 脏位导致后续绘制漏发常量与采样状态。
22. `0021-fd6-zero-unbound-ubo-slots.patch`：这一代 GPU 上 freedreno 用着色器前导码装载常量（`fd6_load_shader_consts_via_preamble`），前导码按着色器用到的范围读每个 UBO 槽，不看主程序的分支。`fd6_emit_ubos` 给未绑定的槽写地址 0，而 Metal 允许运行时不访问的缓冲参数不绑定，前导码读地址 0 时发生 SMMU 翻译故障，内核随即关闭 GPU 提交。补丁给每个上下文分配一块 64 KiB 全零、GPU 只读的 BO（`zero_ubo_mem`），未绑定的槽指向它，并把 `fd_context` 的私有 BO 表从 3 项扩到 4 项。分析与验收见[11-21 真机体验问题 §5](https://github.com/iola1999/hackios-redmi-k90-annibale/blob/main/docs/progress/2026-11-21-user-test-issues.md#5-地图触发的-gpu-停转与整屏闪烁s21)。

23. `0022-ir3-fixed-workgroup-fits.patch`：ir3 对线程组大小固定的计算着色器，不论是否用到 barrier，都把寄存器用量限制在整个线程组能同时驻留的范围内，超出的部分溢出到私有内存。此前只对带 barrier 的着色器这样做，`fd6_get_compute_state_info` 按寄存器用量报告的线程上限可能小于派发要求的线程组。AIR 在派发的线程组超过可变大小编译的上限时，按实际大小另编一份（`tools/mesa/air/air_metal_compute.inc`）。相机拍照处理的 `kernelRec709DownsampleYFilterOrder2`（18×18 线程组）由 47 个寄存器降到 31 个、1536 字节私有内存，派发不再被拒绝，见顶层 `docs/progress/2026-11-21-user-test-issues.md` §16.3。
24. `0024-fd-crash-family-degradation.patch`：针对 backboardd 崩溃族 A、B1 与 B2 的静态修复。`fd_submit_new_ringbuffer` 与 `subpass_create` 检查分配结果并向 `fd_batch_create` 传播失败，batch 分配最多按 1、2、4 ms 退避重试 3 次，仍失败时丢弃本次绘制、清屏、blit 或计算操作；`fd_crb`／`fd_cs` 构造失败后落入进程级 sink 环，写入被丢弃且空环不进入 IB，含 sink 环的 program state 与 compute state 不进缓存，下一次操作重新分配；ir3 variant 的显存上传失败时 variant 不进编译缓存；资源依赖跟踪递归 flush 当前 batch 后停止继续使用该 batch，`cleanup_submit` 释放后清空 `draw` 与 `gmem` 指针。`fd_bo_new` 最终失败时打印 `fd bo new failed`，带尺寸、标志、耗时与线程号。
25. `0025-merge-cleanup-probes.patch`：针对 b5r14 合并清理停滞链（`_slab_destroy_child` ← `flush_deferred_submits` ← `fd_fence_flush`）的诊断探针，叠在 0024 之后应用，不改变降级语义，输出与 `fd bo new failed` 同一 stdout 通道，含线程号。`slab_destroy_child` 的自由链弹出计数超过 10000 时打印链状态并 abort，把秒级自旋变为当场的崩溃与日志；`fd_submit_sp_destroy` 在销毁环池前核对在外的环数，非零时打印账目并 abort；msm 合并清理处打印链长高水位与并入 submit 的引用计数异常；batch 资源跟踪因 0024 的 flushed 提前返回而跳过依赖登记时逐点打印，batch flush 收尾时核对资源集合里的 bo 是否都进了 submit 的 bo 表；`fd6_draw`／`fd6_compute`／`fd6_blitter`／`fd6_query`／`freedreno_query_acc` 的 16 个发射入口读取 `batch->draw` 前检查 NULL，捕获 flush 后继续使用。补丁另含一个独立可回退的 hunk：恢复上游被移植层去掉的 `nr_bos > 30` 延迟合并上限，命中时打印 `fd merge bos cap hit`，用以检验长合并链是否参与故障。

26. `0026-slab-push-time-detection.patch`：slab 自由链损坏机制的诊断轮（判定依据与探针设计见 `out/goal-1124/batch7/slab-corruption-mechanism.md` §6），叠在 0025 之后应用，不改变降级语义。release 构建下被 `NDEBUG` 编译掉的 slab 元素 magic 改为无条件写入与校验：`slab_free` 推入时 magic 非 ALLOCATED（第二次推入的犯罪现场）或自推（`pool->free == elt`）即打印元素头与池状态并 abort；`slab_alloc` 弹出时 magic 非 FREE 同样处理。`fd_ringbuffer_sp` 尾部加金丝雀字段，init 写入 `RINGLIVE`、destroy 校验后改写 `RINGDEAD`：金丝雀既非 LIVE 亦非 DEAD 证明野写进入 ring 对象，读到 DEAD 证明同一对象销毁两次，refcnt 非 0 证明引用计数失衡；三者均打印 ring 状态并 abort。accounting 顺序修正：先按 magic 做全元素普查算出 live 数，再遍历三条链交叉核对，遍历逐节点校验属于池内页面、异常只记录不中断，b5r15 丢失的 live-ring 判定恢复；核对在 `fd_submit_sp_destroy`，live 非零、magic 未知、链异常、普查与链计数不符、在外 ring 金丝雀损坏任一成立即打印全部账目并 abort。犯罪现场打印 `probe frames` 行（dylib 基址加返回地址链，`backtrace()` 原始地址，供离线对 unstripped 库符号化）。递归与降级观测补盲：`fd_batch_check_size` 三处 flush 触发点、`alloc_batch_locked` 槽位耗尽强刷最旧 batch、batch 分配重试与最终放弃（0024 有界重试的静默降级）各加一行计数打印。主机侧功能验证（健康流量零误报、双重释放必抓获 SIGABRT、live 普查正确）与探针输出判别字典见 `out/0026-probes/implementation.md`。

27. `0027-ring-refcnt-history.patch`：ring 双重销毁失衡点定位的诊断轮（判别性探针设计见 `out/goal-1124/batch7/ring-double-destroy-location.md` §5），叠在 0026 之后应用，全部只读与记录，不改变所有权语义。`struct fd_ringbuffer` 内嵌 8 槽环形引用计数转移史：每个 ref/del 点写入（site_id、转移后计数），创建、suballoc 槽位 ref/替换 del、submit destroy 槽位 del、emit unref del、cleanup_submit 各字段 del、subpass 系 del、primary ref/del、对象环 CSO 系 del 与 fastpath ref 各占一个 site id，未标注调用点记 unknown；二次销毁等三类 ring 违规打印全部 8 槽与对应 site 名，配平流式环历史固定为 `create1 subref2 subdel1 emitdel0`，多出的 del 的 site 直接给出失衡点。`fd_submit_sp_destroy` 改为先清空 suballoc 槽位再归还引用，ring 销毁时仍在槽位即打印 `fd ring in suballoc slot` 并 abort（计数算术已错的当场报告，比第二次 del 早一个环节）。flush 重入检测：`fd6_draw_vbos` 与 `fd6_emit_3d_state` 进出各升降 ctx 发射段深度，`fd_batch_flush` 入口深度非零即打印 `fd flush inside emit`（被刷 batch 与当前 batch 并列，相等才是形态乙证据）并附帧链。tile 系环（tile_loads/tile_store/subpass_clears）创建时打印 `fd tile ring create`（种类、ring、submit、seqno），供与历史交叉对照，每进程限 256 行。主机侧功能验证（健康流量零误报、双重释放历史含致命条目、槽位不变量命中）与输出判别字典见 `out/0027-probes/implementation.md`。

28. `0028-fd6-emit-ownership-probes.patch`：fd6 发射路径双重消费修复与 emitdel sharpen 探针，叠在 0027 之后应用。
    - 修复：`fd6_state_take_group` 在同一 state 对象已有同一 ring 的 unref 槽时，为新 take 槽补一条引用，记账方式与对象环 fastpath 的 ref+take 相同；`fd6_state_emit` 消费组后清空槽位，结束时清零 `num_groups`。
    - 探针：0027 的 hist 条目扩展 `group_id` 与发射 pass，emitdel 打印 `group %u pass %u`；同一 ring 的两条 emitdel pass 相同表示同一次发射内两次消费。重复入组补偿命中时打印 `fd state duplicate take`（ring、两个 group 与槽位、线程号，每进程 16 行上限）。
    - 验证：主机 harness 覆盖正常生命周期、入组点补偿、发射消费终止化、补偿后双 take 生命周期、双重销毁打印和槽位不变量，见 `out/0028-probes/implementation.md`。

29. `0029-suballoc-install-ref-fix.patch`：suballoc 安装引用缺失修复与安装点防回归探针，叠在 0028 之后应用。
    - 修复：`fd_submit_sp_new_ringbuffer` 在 `refcnt = 1` 相邻处提前写入 `flags`，使流式环安装路径的 sink 判别读取本世代值；`fd_ringbuffer_sp_init` 内同值重写保留。init 失败路径回退为上游的直接 `return NULL`，已装槽环不再退回 slab 池。
    - 探针：`fd_submit_suballoc_ring_bo` 装槽前若读出 sink 标志，打印 `fd suballoc sink install`（ring、flags、pid、tid）与帧链，每进程 16 行上限；0029 修复后预期零命中。0026 canary/magic、0027 hist 与槽位不变量、0028 duplicate-take 补偿及归属探针保持不变。
